# V003: Open source, local MCP, no hosting

> Status: superseded (V004: the hosted connector is the default, the local server the pro option. Open source, npm, extensions and the landing page still hold)
> Type: vision
> Date: 2026-10-20
> Supersedes: V002-mcp-first.md (the layers, tools and principles of V002 still hold, distribution and storage change)

## Problem

V002 planned hosting later (HTTP MCP, AWS). InstaDeck however needs Chromium (overflow measurement, previews for the model, PDF), and its outputs are files the user wants to keep. Hosting would mean a container with Chromium, moving outputs around and state on our side. A local MCP server needs none of that.

## Design

- **Open source under MIT**, repo `schinkodev/instadeck`, package `instadeck` on npm. Domain `instadeck.app` for the landing page.
- **A local MCP server on the user's machine** (stdio), the same pattern as Playwright MCP:
  - Claude Code: `claude mcp add instadeck -- npx -y instadeck`
  - Claude Desktop: the `instadeck.mcpb` extension (MCP Bundle, Node ships with Claude Desktop), the user picks a folder for decks during installation
- **Zero running costs for us.** No server, no state on our side, the user's model does all the work on content. Only the domain is paid for.
- **The user's Chromium.** `puppeteer-core` with an installed Chrome, Edge or Chromium (or a path in `INSTADECK_CHROME`). No 150 MB browser download during installation.
- **Outputs are files the user can see:**

```
~/InstaDeck/                       INSTADECK_HOME, the chosen folder in Claude Desktop
  northwind-seed-pitch/            one folder = one deck, the deck id is the folder name
    deck.html                      the animated presentation, can also be printed to PDF
    deck.pdf                       after export_deck
    deck.json                      source of truth (slides, design, motion)
    .revisions/<n>.json            history
  .assets/  .brand-kits/           shared between decks
```

- **PDF without a server:** the presentation has print CSS, printing from the browser (Cmd+P, Save as PDF) gives the same PDF as `export_deck`.
- **A static landing page** on `instadeck.app` (GitHub Pages): a live example deck right on the page, a one line install, a button for Claude Desktop.
- **Later, depending on interest:** `share_deck` as the only hosted part (uploading the finished HTML to hosted storage, a small stateless service without Chromium). A desktop app that installs and promotes the same MCP server.

### Rules

- Everything a client does goes through MCP tools and resources. A desktop app or the landing page call the same tools as the model.
- A feature the model does not learn from a tool description, the `instructions` or a resource does not exist in practice.
- What the server does not have is not promised. Planned things are in `server/capabilities.ts` as `planned`.

## Implementation

1. **Package:** an esbuild bundle `dist/instadeck.js` with `bin`, `files`, the MIT license, `puppeteer-core` and browser discovery, deck folders by name, print to PDF in the presentation.
2. **Claude Desktop:** `manifest.json` (MCPB 0.3), `npm run bundle` produces `instadeck.mcpb`.
3. **Landing page:** `site/`, generated by a script including the example deck, a workflow for GitHub Pages (enabling it and DNS only on the owner's go).
4. **Publishing on the owner's go:** making the repo public, `npm publish`, a GitHub Release with the `.mcpb`, DNS for `instadeck.app` on GitHub Pages.

## Acceptance Criteria

- [x] `npm pack` produces a package that, installed into an empty folder, starts the MCP server through `npx instadeck`
- [x] The server finds an installed Chrome, without a browser it ends with a clear error and instructions
- [x] A deck is a folder with `deck.html`, `deck.json` and history, the deck id is the folder name
- [x] Printing the presentation from the browser gives one page per slide with all steps revealed (test in Chromium, Safari by hand)
- [x] `instadeck.mcpb` passes `mcpb` validation and includes picking the deck folder
- [x] The landing page works locally with a live example deck, without the word AI and without an em dash
- [x] Nothing is published or deployed without the owner's go
